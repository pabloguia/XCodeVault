# S4 — Savings-first GUI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The app opens on what the user can reclaim — temporarily and permanently — with one screen per way of reclaiming, one place for access, the brand, and five languages.

**Architecture:** Every number and every decision comes from Core and is tested there (`SavingsSummary`, `SavingsPlanner` rows with `actsImmediately`/`noteIDs`/`itemCount`, new `DiskBar` and `AccessChecklist` models); SwiftUI views only render. All app text goes through `L10n.tr("app.…")` and renders with `Text(verbatim:)`. The app seeds `L10n` from `Bundle.main.preferredLocalizations` once at launch. No new writer: Park and Run-externally show plans with a **Copy command** button (spec §6.4); deletion keeps today's Clean semantics.

**Tech Stack:** Swift 6, SwiftUI (macOS 14), AppKit (`NSPasteboard`, `NSHostingView` for off-screen snapshots), XCTest, the S2 `L10n` layer, S3 Core models, S5 brand tokens.

**Spec:** `docs/superpowers/specs/2026-10-03-savings-visibility-i18n-identity-design.md` §6, §6.1–6.4, §7, §10 (all S4 carry-overs), §3.4, §4.6, §5.1.

## Global Constraints

- Branch `feat/gui-savings` from `feat/identity` (S5 merged into the line). No push inside tasks.
- Views decide nothing: every derivation is a Core function with a test, or an `AppModel` method tested through `AppEnvironment` fakes. Tests never scan this Mac, write the real journal, touch launchd, open System Settings, or put a window on screen (off-screen `NSHostingView` only).
- No GUI writer for park/run-externally/locations (§6.4). Delete keeps `CleanExecutor` semantics, the Trash toggle (default on), the exact-count confirmation and journaling. Rule 5: Archives never in the Delete view. Rule 10: experimental badges wherever a row is experimental.
- Text: `L10n.tr("app.…")` literal keys, `Text(verbatim:)` always (never `Text("literal")`, which would re-interpret `%` and look up `LocalizedStringKey`); drafts pt-BR, es, ja, zh-Hans `needs_review`; numbers/bytes via `ByteCount.format` (follows `L10n.locale`); Core prose (findings) stays English — render it as given.
- Never color alone: every bucket shows symbol + localized title + color (S5 tokens).
- Legacy `ScanSummary` fields (`verifiedSavingsBytes`, `estimatedInternalSavingsBytes`, the "of which runtime images" row) are no longer rendered (§10).
- The simulator-runtime `.dmg` gap: show `summary.runtimeImageBytes` as its own line, as `scan` does (S3 final fix C5).
- Swift 6, macOS 14+, 160 columns, swift-format strict. Slow machine: focused class filters; full preflight in the last task.

### Task 1: Core view models — `DiskBar` and `AccessChecklist`

**Files:** `Sources/XCodeVaultCore/Savings/DiskBar.swift`, `Sources/XCodeVaultCore/Permissions/AccessChecklist.swift`; tests `DiskBarTests`, `AccessChecklistTests`.

- `public struct DiskBar { public struct Segment { kind: Kind; bytes: UInt64 }; public enum Kind { case otherData, bucket(SavingsBucket), free }; public static func segments(host: HostEnvironment, savings: SavingsSummary) -> [Segment] }` — developer data split by `primaryBytes` per bucket (order: runFromExternal, parkExternally, deleteAndRegenerate, keepLocal), `free = dataVolumeFreeBytes`, `otherData = total − free − Σ primary` clamped at 0. Tests: segments sum to `dataVolumeTotalBytes` (unless clamped — then a flag `isClamped`), zero-byte buckets omitted, order fixed.
- `public struct AccessChecklist { public struct Row { need: Need; state; whyKey: String; actionKey: String?; blocksBytes: UInt64? } ; public static func rows(fullDiskAccess:helper:savings:plan:) -> [Row] }` — one row for Full Disk Access, one for the helper; `why` text keys say what is blocked in bytes when known (FDA: "lets XCodeVault measure folders it cannot read now" — no byte count because unread bytes are unmeasurable; helper: the bytes of root-only rows, e.g. the dyld caches). Helper unavailable in this build: the action key points to the CLI/“signed release” wording, never "Not available in this build" alone (§6.3). Tests per state combination.

### Task 3: Navigation and the Overview dashboard

**Files:** `XCodeVaultApp.swift` (split `MainView`, `OverviewView` into `Sources/XCodeVault/Views/…` files if `XCodeVaultApp.swift` exceeds ~600 lines — it is already 626), tests.

- Sidebar (§6.1): two `Section`s — "Save space": Overview, Delete, Park, Run externally; "Details": Storage, Simulators, Drives, Health, History, Access. Each with its SF Symbol (buckets use S5 symbols).
- Overview (§6.2): host line; the `DiskBar` as a horizontal stacked bar (bucket colors from S5, other data neutral, free light) with a legend (symbol + title + size); three cards — Temporary (delete), Temporary (park), Permanent (run externally) — each: big "up to"/"at least" amount (`optionBytes`), verified share, the bucket's promise and undo cost, the delete card's "of which X deletes apps' data" line (S3 A), a **Review** button that selects that bucket view; the alternatives note with the union total; the runtimes-measured-by-simctl line when > 0; at most one access banner (the first `AccessChecklist` row that blocks something) and the critical findings group. `--no-sizes` has no GUI equivalent; if `report.sizesMeasured == false`, show the not-measured message instead of cards.
- Tests: model-level (which card values come from which `SavingsSummary` field — extract a tiny `OverviewCards.make(savings:)` in Core or the app and test it), render tests in every locale and for lower-bound / zero / not-measured states.
